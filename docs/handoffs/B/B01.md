## Completed deliverables

- `src/kerberos_lab/kdc/app.py`: settings-aware Flask factory and process CLI, startup loading of role-scoped private material and TGS replay store, implemented health response, `/login`, `/service-ticket`, strict JSON/schema/error handling and loopback-only runtime binding.
- `tests/integration/test_b_kdc.py`: 11 HTTP-level integration cases using actual AES-GCM tickets, HMAC authenticators, Scrypt verification and temporary SQLite stores.
- This handoff records implementation behavior, checks, platform limits and remaining integration boundaries.

The AS issues an opaque TGT under the TGS key and separately returns its client/TGS session data. Login rejects unknown users and wrong passwords with the same public 401 response. The TGS opens only a TGT with the TGS key, validates the TGS-bound authenticator and time using one captured logical time, authorizes `files`, consumes the TGS replay identity, and returns a separately keyed service ticket encrypted under the service key. TGS replay consumption remains enabled even when resource `defense_mode` is `authenticator_no_cache`. Error bodies use the shared public mapping and contain no diagnostic reason or secret.

The CLI requires `--run-dir` and supports `--config`, `--port`, `--clock-offset-seconds`, and `--frozen-time-seconds`; it binds to validated loopback settings with debug/reloader disabled. There is no KDC `--defense-mode` option.
