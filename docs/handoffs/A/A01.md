## Decisions frozen for implementation

- Custom v1 loopback protocol; separate TGS/resource keys and session relationships.
- AES-256-GCM envelopes with kind-bound AAD and fresh internally generated encryption nonces; HMAC-SHA256 authenticators bind ticket, endpoint, service and body.
- Integer seconds; 300-second ticket lifetime, 30-second authenticator tolerance and ticket leeway, all specified equality boundaries inclusive.
- Separate TGS/resource SQLite stores with run/namespace/schema metadata, open-existing behavior, atomic consume/counter updates and full-run record retention.
- Fresh run-directory initialization only; no silent state recreation or destructive reset flag.
- Resource modes differ only in replay consumption; KDC/TGS behavior stays constant.
- Library Scrypt login verifier and parameter-recorded PBKDF2-SHA256 helper for the optional service-password demo; these are simulator choices, not real AD profiles.
- Runtime configuration/clock changes are local process/test controls, not HTTP debug endpoints.

Routine choices were resolved within the approved scope. No unresolved design decision blocks A02; implementation findings requiring an incompatible change must revise the contract/fixtures before G1 release.
