## TDD and evidence

The user requested TDD. Agreed public seams are the released launcher/CLI flags and actual client/HTTP interfaces. First real-flow test failed because the old launcher omitted required child `--run-dir`; launcher implementation made the full journey pass. A POSIX SIGTERM test then failed because the launcher left children listening; explicit signal handling made it pass and both ports close. Remaining integration regressions passed on those capability implementations; not every case was independently observed failing first.

Actual tested behaviors:

- AS login → TGT → authenticated TGS request → service ticket → two fresh resource operations using that ticket, followed by duplicate rejection. Counters are 1 and 2, and an exact repeat returns 409.
- Wrong username/password uniformly return 401; an authenticated unsupported TGS service returns 403; neither executes the resource. Both resource modes retain those checks.
- KDC-issued artifacts reject modified encrypted ticket/MAC/identity/service/path, unsupported operation and a real TGT used at the resource. Counter remains zero after each invalid request and the untouched original then commits once, in both modes.
- After logical server time advances via process restart, old TGT and service ticket fail with fresh-time authenticators. New login/grants at that logical time succeed. No host clock changes.
- Exact capture save/load preserves bytes. After restarting the full lab on the same directory, defended replay remains 409/counter=1; no-cache replay commits counter=2.
- Actual setup CLI, launcher, health CLI, client `run --count 2 --capture`, and replay CLI work on Linux with real-time servers. The client password prompt is exercised via detached stdin fallback in the automated test, not a mock or password argv. Interactive users use getpass normally. Console output excludes the disposable password/session-key/ciphertext fields.
- Config paths/run paths with spaces, nondefault ports, zero-skew TOML, both role clock offsets, frozen time, and CLI resource-mode override reach real child processes correctly.
- Graceful interruption closes both child listening ports; POSIX SIGTERM does too. Resource startup failure stops the sibling and does not recreate missing state. Conflicting ports are rejected before child startup.

## Limits

This validates the implemented educational flow, not a novel protocol, production Kerberos/AD compatibility or a security proof. Password/session delivery over loopback JSON is the declared simulator simplification. No benchmark, reviewed E01–E10 evidence, optional guessing experiment, plot or paper result is produced here. Ordinary process restart is not power-loss testing or hostile local rollback resistance. Replay rejection does not recover a lost response after commit. The launcher's spawned message is not a readiness guarantee; clients must check health. Force-killing the parent bypasses cleanup; native Windows lifecycle and ACL guarantees are not claimed.
