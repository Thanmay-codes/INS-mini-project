# Common task execution rules

1. Read root `AGENTS.md`, `PROJECT_CONTEXT.md`, your one task prompt, and `docs/workflow/README.md`. Read the task's specific source sections; avoid unrelated historical proposal files unless needed. The implementation plan specifies behavior; the workflow specifies execution order and file ownership.
2. Inspect `git status --short`, current branch and starting commit. The human should have created the prompt's fresh branch from current main, recorded BASE_SHA, and merged all prerequisites. Preserve user changes. If the checkout is dirty/unexpected or dependencies are absent, report the exact blocker before changing implementation files. B00 can run before G1. C01/D01 use clearly labeled planned content.
3. Complete ONLY this task. Limit edits to its listed outputs within your role's allowlist in `docs/workflow/tasks.json`. Changing a shared dependency, schema, root README, configuration or central context belongs to A. Put requests for another owner's files in your own handoff; do not work around a missing helper with a competing implementation.
4. Use the contract released by A; import shared helpers rather than copying cryptography or clock rules. Claims of actual behavior require code/checks; planned diagrams and placeholders must remain labeled. Raw evidence stays in ignored paths; only A publishes reviewed sanitized results.
5. Run relevant checks for the behavior changed. Record exact commands, failures and fixes. An empty pytest suite or mocked flow is not evidence of a working end-to-end protocol. C/D documentation tasks require source/link/caption checks rather than invented code tests.
6. Write `docs/handoffs/<ROLE>/<TASK>.md` using the template. Include BASE_SHA, changed paths, commands/outcomes, dependencies, proposed out-of-scope changes and remaining limitations. Record status as implementation ready for review, support draft ready, or blocked; only A releases a project gate after merge and integration checks.
7. Run `python scripts/check_task_scope.py --role <ROLE> --base <BASE_SHA>` from the project environment. Fix out-of-scope edits without discarding unrelated user changes; otherwise describe the boundary issue. The checker is advisory and does not establish security correctness.
8. Finish by reporting the deliverables, checks and next human handoff. Leave commits, pushes, remote sync and credential-requiring operations to the human. Never place credentials, live tickets, session keys or replay databases into tracked artifacts.

Before a new task begins, the human commits/reviews the previous task and syncs an appropriately fresh branch. Passing a prompt from a cheaper model to a stronger reviewer is encouraged for security-critical work; neither should infer a released gate from prose alone.
